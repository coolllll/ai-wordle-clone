# Design

## Context

ดูแรงจูงใจที่ proposal.md และพฤติกรรมใน `specs/leaderboard/spec.md`

หน้า `/history` อยู่ใน `src/app/(game)/history/page.tsx` กลุ่มเส้นทางนี้ส่งคนไม่มีเซสชันไป `/login` และหุ้มด้วย `AppShell` ซึ่งมีลิงก์ History ไป `/history` หน้าประวัติอ่านเกมผ่าน `getHistory` บนเซิร์ฟเวอร์ตอนเปิดหน้า `toHistory` ให้คะแนนเฉพาะเกมที่ชนะเป็นจำนวนครั้งที่ทาย และเกมที่แพ้ไม่มีคะแนน เกมอยู่ที่ `data/games.json` พร้อม `userId` กับ `completedAt` ชื่อผู้ใช้อยู่ที่ `data/users.json` คนละไฟล์ `readUsers` ยังไม่เปิดรายชื่อออกนอก `accounts.ts`

## Goals / Non-Goals

**Goals:**

- คำนวณอันดับจากเกมที่ชนะและชื่อผู้ใช้ที่มีอยู่ โดยไม่เก็บตารางอันดับแยก
- ให้หน้า leaderboard ใช้การกันเซสชันและ shell ชุดเดียวกับหน้าประวัติ
- ไม่ส่งคำตอบหรือรายการคำทายออกจากหน้าที่จัดอันดับ

**Non-Goals:**

- ไม่เพิ่ม `GET` API ใหม่สำหรับอันดับ
- ไม่เปลี่ยน `GET /api/history`, หน้าประวัติ, หรือรายการบนหน้าเกม
- ไม่ทำอันดับอัปเดตเองขณะผู้ใช้ค้างอยู่บนหน้า

## Decisions

### 1. วางหน้าไว้ในกลุ่ม `(game)`

สร้าง `src/app/(game)/leaderboard/page.tsx` เพื่อใช้ layout ที่พาไป `/login` เมื่อไม่มีเซสชัน และใช้ `AppShell` เดิม เพิ่มลิงก์ Leaderboard ชี้ `/leaderboard` คู่กับ History หัวข้อบนหน้าคือ Leaderboard

ทางเลือกที่ตัดไป: หน้าอยู่นอกกลุ่ม `(game)` แล้วตรวจเซสชันซ้ำอีกชุด

### 2. ฟังก์ชันจัดอันดับบริสุทธิ์

เพิ่มฟังก์ชันที่รับเกมที่บันทึกไว้กับ `{ id, username }` แล้วคืนแถว `{ rank, username, score }`

- ใช้เฉพาะเกม `won` ที่มี `userId` และ `completedAt`
- คะแนนของบัญชีคือ `guesses.length` ที่น้อยที่สุด
- เวลาที่ใช้ตัดสินเสมอคือ `completedAt` ที่เก่าที่สุดในบรรดาชัยชนะที่เท่ากับคะแนนนั้น
- ตัดบัญชีที่ไม่มีชื่อในรายชื่อผู้ใช้
- เรียงคะแนนจากน้อยไปมาก แล้วเวลาจากก่อนไปหลัง แล้วชื่อที่เก็บไว้จากน้อยไปมากด้วย `localeCompare`
- `rank` คือลำดับที่บวกหนึ่ง จึงเป็น 1, 2, 3

ทางเลือกที่ตัดไป: ให้หน้าประวัติคำนวณอันดับให้ เพราะ `toHistory` ตั้งใจคืนเกมของบัญชีเดียวพร้อมคำตอบ

### 3. อ่านชื่อผู้ใช้โดยไม่เปิดแฮชรหัสผ่าน

เพิ่มตัวอ่านใน `accounts.ts` ที่คืน `id` กับ `username` จาก `readUsers` หน้า leaderboard อ่านเกมกับรายชื่อนี้บนเซิร์ฟเวอร์ตอนเปิดหน้าครั้งเดียว ไม่มี interval หรือ client refetch

ทางเลือกที่ตัดไป: ให้หน้าเกมหรือ `GET /api/history` คืนอันดับรวม เพราะจุดนั้นผูกกับบัญชีผู้เรียกและมีคำตอบอยู่ในประวัติ

### 4. ว่างและผิดพลาดเป็นคนละสถานะ

ไม่มีผู้ชนะ: หัวข้อ Leaderboard กับข้อความ `No wins yet.` และไม่มีแถวอันดับ อ่านที่เก็บไม่สำเร็จ: `role="alert"` ข้อความ `The leaderboard could not be loaded.` และไม่มีแถวอันดับ ไม่ใช้ข้อความของหน้าประวัติที่บอกว่าผลล่าสุดไม่ได้ถูกบันทึก

## Risks / Trade-offs

- [เกมชนะที่ `userId` ไม่ตรงผู้ใช้ที่ยังมีอยู่] → ไม่ใส่แถวนั้น
- [ชื่อผู้ใช้เรียงด้วย `localeCompare` อาจไม่ตรงการเรียงพจนานุกรมภาษาอื่น] → ใช้ลำดับนี้ให้เทสต์ยึดได้ และเทียบกับชื่อที่เก็บจริง
- [หน้าเกมเห็นลิงก์ Leaderboard เพราะใช้ shell เดียวกัน] → ลิงก์เป็นทางเข้า ไม่ใช่แถวอันดับ หน้าเกมยังไม่เรนเดอร์รายการ

## Migration Plan

ไม่มีข้อมูลให้ย้าย อันดับคำนวณจาก `games.json` กับ `users.json` ที่มีอยู่ ย้อนกลับได้โดยเอาหน้า ลิงก์ และฟังก์ชันจัดอันดับออก
