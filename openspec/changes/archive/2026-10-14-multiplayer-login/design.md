# Design

## Context

ดูแรงจูงใจที่ proposal.md พฤติกรรมที่ต้องได้ระบุใน `specs/player-auth/spec.md` และ `specs/score-history/spec.md`

ตอนนี้ `src/app/page.tsx` เปิด `GameClient` ได้ทันที และ `GET /api/history` คืนทุกเกมที่จบใน `data/games.json` `GameRecord` ไม่มีเจ้าของ `StoreData` มีแค่ `games` แอปใช้ Next.js 15 และ Tailwind v4 โดยไม่มีไลบรารีฟอร์มหรือระบบล็อกอิน หน้าอ้างอิงเป็นโครงภาพ ไม่ใช่บริการที่จะเชื่อม

## Goals / Non-Goals

**Goals:**

- กันหน้าเกม หน้าประวัติ และ API ของเกมไว้หลังเซสชันของบัญชีบนเซิร์ฟเวอร์นี้
- ให้หน้า login และหน้าสร้างบัญชีใช้โครงเดียวกับการ์ดอ้างอิง โดยเป็นของ Word Guess
- ผูกเกมใหม่และประวัติกับบัญชีเจ้าของ

**Non-Goals:**

- ไม่ทำ MFA, OAuth, รีเซ็ตรหัสผ่าน หรือเกมที่ผู้เล่นหลายคนทายพร้อมกัน
- ไม่ย้ายธีม daisyUI ของหน้าเกมใน change นี้
- ไม่นำเรคอร์ดเก่าที่ไม่มีเจ้าของไปใส่ให้บัญชีใด

## Decisions

### บัญชีแยกจากไฟล์เกม

เก็บบัญชีใน `data/users.json` คนละไฟล์กับ `data/games.json` เพื่อไม่ให้ตัวอ่านเกมเดิมต้องยอมรับโครงผู้ใช้ บัญชีมี `id`, `username` และรหัสผ่านที่แฮชด้วย `scrypt` ของ `node:crypto` ไม่เพิ่ม dependency

ทางเลือกที่ตัดไป: ใส่ผู้ใช้ลงใน `StoreData` เดียวกับเกม ทำให้ตัวตรวจความถูกต้องของเกมและเทสต์เก็บข้อมูลผูกกับบัญชีโดยไม่จำเป็น

### เซสชันเป็นคุกกี้ที่เซ็นแล้ว

หลังเข้าสู่ระบบหรือสร้างบัญชี เซิร์ฟเวอร์ตั้งคุกกี้ `httpOnly` ที่ลงลายเซ็นด้วย HMAC คุกกี้เก็บรหัสบัญชี ไม่เก็บรหัสผ่าน คีย์ลายเซ็นอยู่ใน `data/session-secret` และถูกสร้างเมื่อยังไม่มีไฟล์ ไม่ commit คีย์นี้ เซสชันอยู่ได้ 7 วัน และยังใช้ได้หลัง reload

ทางเลือกที่ตัดไป: เก็บรหัสบัญชีใน `localStorage` เพราะหน้าและ API ถูกเรียกโดยไม่มีหลักฐานที่เซิร์ฟเวอร์ตรวจได้

### หน้า login ไม่ใช้ shell ของเกม

`/login` และ `/register` เป็นหน้าเต็มจอพื้นขาว การ์ดกลางกว้างประมาณ 400px มีชื่อ Word Guess ช่อง Username กับ Password ปุ่มเต็มแถว และ footer ใช้ Tailwind utility โดยตรง ไม่ใช้คอมโพเนนต์หรือโลโก้ของ Warroom ฟอร์มเป็นฟอร์มของเบราว์เซอร์เพราะโปรเจกต์ไม่มีไลบรารีฟอร์ม มีลิงก์สลับระหว่างสองหน้า การ์ดสร้างบัญชีใช้โครงเดียวกัน

หน้า `/` และ `/history` ยังอยู่ใน `AppShell` และเพิ่มชื่อผู้ใช้กับปุ่มออกจากระบบ ผู้ไม่มีเซสชันถูกส่งไป `/login`

### เกมใหม่ต้องมีเจ้าของ

`GameRecord` ใหม่มี `userId` API สร้าง อ่าน และทายคำตรวจเซสชันแล้วเลือกเฉพาะเกมของบัญชีนั้น เกมของคนอื่นตอบเหมือนไม่พบ โดยไม่คืนคำตอบหรือสถานะ เกมเก่าที่ไม่มี `userId` ไม่ถูกเปิดและไม่เข้าประวัติ

`toHistory` และ `GET /api/history` กรองด้วย `userId` ของเซสชันก่อนเรียงจากใหม่ไปเก่า

## Risks / Trade-offs

- [เรคอร์ดเก่าไม่มีเจ้าของจึงหายจากหน้าประวัติ] → ไม่โยกให้บัญชีใดโดยอัตโนมัติ เพราะไม่มีทางรู้ว่าเป็นของใคร ไฟล์เดิมยังอยู่
- [คีย์เซสชันอยู่ในเครื่องเดียวกับข้อมูลเกม] → พอสำหรับแอปท้องถิ่นนี้ และไม่ส่งรหัสผ่านกลับไปที่เบราว์เซอร์
- [หน้า login ใช้ utility ตรง ขณะที่หน้าเกมยังใช้ daisyUI] → แยกหน้ากัน change ถอด daisyUI ที่มีอยู่แล้วไม่ต้องเสร็จก่อน

## Migration Plan

1. เพิ่มไฟล์ผู้ใช้และฟิลด์ `userId` โดยยังอ่าน `games.json` เดิมได้
2. เปิดเส้นทาง login กับ register แล้วกันหน้าเกม หน้าประวัติ และ API
3. ถ้าต้องย้อนกลับ ให้เลิกบังคับเซสชันที่หน้าและ API ไฟล์เกมเดิมยังอ่านได้เพราะ `userId` เป็นฟิลด์เพิ่ม
