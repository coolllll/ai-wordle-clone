# Design

## Context

ดูแรงจูงใจที่ proposal.md พฤติกรรมที่เพิ่มระบุใน `specs/score-history/spec.md`

หน้าเกมเรนเดอร์ `GameClient` ซึ่งมีสถานะของเกมปัจจุบัน กระดาน แป้นพิมพ์ และปุ่ม New game อยู่แล้ว ใต้ส่วนนั้นมี `section` ที่ `data-testid="history-panel"` หัวข้อ Recent games และ `HistoryList` คอมโพเนนต์เรียก `fetchHistory()` จาก `src/lib/client-api.ts` ตอนเปิดหน้า และเรียกซ้ำหลังบันทึกผลผ่าน `historyVersion` หน้า `/history` โหลดรายการเดียวกันฝั่งเซิร์ฟเวอร์ด้วย `getHistory()` แล้วเรนเดอร์ `HistoryList` ลิงก์ History อยู่ใน `AppShell`

## Goals / Non-Goals

**Goals:**

- ให้หน้าเกมไม่มีรายการเกมที่จบแล้ว และไม่เรียกประวัติมาแสดง
- คงสถานะชนะหรือแพ้ของเกมปัจจุบัน ปุ่มเริ่มเกมใหม่ และหน้าประวัติ

**Non-Goals:**

- ไม่เปลี่ยนรูปแบบเรคอร์ด การเรียงลำดับ หรือ `GET /api/history`
- ไม่ย้ายหรือลบ `HistoryList` และหน้า `/history`
- ไม่กำหนดการแยกประวัติตามบัญชี ซึ่งเป็นของ change `multiplayer-login`

## Decisions

### ถอดเฉพาะแผงบนหน้าเกม

ลบ state `history`, `historyVersion`, effect ที่เรียก `fetchHistory` และการเพิ่ม `historyVersion` หลังทายสำเร็จออกจาก `GameClient` พร้อมกับ `section` Recent games สถานะ `You won` / `You lost` ปุ่ม New game และ alert ของการทายหรือการบันทึกผลยังอยู่

ทางเลือกที่ตัดไป: เหลือรายการสั้นแค่เกมล่าสุดหนึ่งรายการบนหน้าเกม เพราะยังซ้ำกับหน้าประวัติและยังต้องดึงประวัติ

### ให้หน้าประวัติเป็นที่เดียวที่แสดงรายการ

`/history` ยังใช้ `getHistory()` และ `HistoryList` ถ้า `fetchHistory` ไม่มีผู้เรียกเหลือหลังถอดแผง ให้ลบฟังก์ชันนั้นออกจาก `client-api` โดยไม่ลบ route `GET /api/history`

ทางเลือกที่ตัดไป: คง `fetchHistory` ไว้เผื่อใช้ต่อ ทั้งที่ไม่มีผู้เรียกบนหน้าเกม

### ปรับเทสต์ของหน้าเกมให้ตรงกับพื้นผิวที่เหลือ

เทสต์ที่เรนเดอร์ `GameClient` แล้วคาด `history-result` หรือจำนวนครั้งที่เรียก `/api/history` เพื่อรีเฟรชแผง ให้เปลี่ยนไปตรวจว่าหน้าเกมไม่มี `history-panel` และไม่เรียก `/api/history` เทสต์ชนะ แพ้ และการบันทึกผลล้มเหลวยังตรวจข้อความสถานะเดิม เทสต์ของ `HistoryList` และ e2e ที่เปิด `/history` ไม่ต้องเปลี่ยนพฤติกรรม

## Risks / Trade-offs

- [ผู้เล่นไม่เห็นรายการใต้กระดานทันทีหลังจบเกม] → ลิงก์ History ใน `AppShell` ยังพาไปหน้าประวัติ และสถานะของเกมปัจจุบันยังอยู่บนหน้าเกม
- [change `multiplayer-login` อาจแตะ `GameClient` หรือ `GET /api/history` ภายหลัง] → change นี้ไม่เปลี่ยนตัวกรองประวัติ ถ้างานนั้นใส่รายการกลับบนหน้าเกม จะขัด spec นี้

## Migration Plan

ไม่มีข้อมูลให้ย้าย การนำขึ้นคือการเอาแผงและคำขอดึงประวัติออกจากหน้าเกม ถ้าต้องย้อนกลับ ให้คืน `section` และ effect เดิมใน `GameClient` โดยไม่ต้องแก้ไฟล์ JSON
